## 字体覆盖离线验证

【源码确认】Kconfig 为 ET013TT1 默认选择 IBMF；Fonts.cpp 内置 SolSans 三个 face，
TTF 分支使用 NotoSansLight 与 SolPrivate，字体管理已有统一 API。
【离线验证】本项目 audit_fonts.py 读取真实字库，结果：
| 文件 | Unicode 映射码点数 | U+4E00..U+9FFF |
| --- | --- | --- |
| IBMFFonts/SolSans_75.ibmf | 1259 | 0 |
| IBMFFonts/NotoSans-Light.ttf | 2793 | 0 |
| TTFFonts/SolPrivate-Light.ttf | 6 | 0 |

“中文阅读，。”在这三个资源中都没有覆盖；SolSans/NotoSans 的 ASCII 样本存在。
TTF 结果也用已安装 fontTools 独立读取 cmap 交叉核对，未安装依赖。
IBMF 目录格式依据 IBMFDefs.hpp 的 Preamble/Planes/CodePointBundle，
本项目只实现读取目录的原创工具，没有复制上游字体。
【阻断】中文资源须另选明确授权、固定版本的字体并生成覆盖报告，
保留原厂私有图标/ASCII；目前没有选定或下载新中文字体。

## 中文特有缺口

【源码确认】[src/Renderers/TxtTokenizer.cpp:109](https://github.com/sindarin-inc/embedded-app/blob/7dcf0850daa5cec076c8d68e2f56cf413ff707aa/src/Renderers/TxtTokenizer.cpp#L109) 当前按空格/连字符组织 TEXT，
循环对高位字节继续读取；[src/Renderers/TxtTokenizer.cpp:254](https://github.com/sindarin-inc/embedded-app/blob/7dcf0850daa5cec076c8d68e2f56cf413ff707aa/src/Renderers/TxtTokenizer.cpp#L254) 跳转先寻找空格/连字符边界。
【推断】无空格长中文段落可能形成大 token、越过目标跳转位置，
在 token/pool 上限处出现边界问题；需要离线中文用例证明，不能说实机已出现。
[src/Renderers/Pager.cpp:45](https://github.com/sindarin-inc/embedded-app/blob/7dcf0850daa5cec076c8d68e2f56cf413ff707aa/src/Renderers/Pager.cpp#L45) 主要按 token 像素宽度换行；
所审 v1.6.0 的 tokenizer/pager 未找到完整中文字符级分割和中文禁则表。
UTF8Iterator 未完整验证过长编码、代理项和码点上限；
未来应定义严格输入策略，避免非法字节造成游标和绘制错误。

【源码确认】上游另有 guy/CJK-demonstration 分支，
固定 SHA=d2f005c661405c910d6663bcbd7b77a73ebfa26f，包含 CJK 排版实验历史。
【离线验证】该提交不是 v1.6.0 的祖先；
不能把分支实验当成已发布、First Edition 兼容或已测试的中文支持。
可参考真实实现思路，先审计差异和许可，不整分支覆盖硬件基线。

【阻断】已检出引擎未找到 GBK/GB18030 转换入口。
【推断】优先由电脑导入工具转 UTF-8，保留原始文件哈希、编码信息与转换版本；
设备端仅使用规范化 UTF-8 稳定位置。特殊需求再评估设备端表大小与资源。

## 内存与性能边界

【源码确认】[src/Kconfig.projbuild:285](https://github.com/sindarin-inc/embedded-app/blob/7dcf0850daa5cec076c8d68e2f56cf413ff707aa/src/Kconfig.projbuild#L285) 默认 paragraph=5003字节、
page=2400字节、CStr pool=2000字节、token=500、line=200字节、line count=36；
RendererDefs 采用有上限数组，EPUB/解压/流和 PSRAM 分配无需把整本书加载入内存。
这些是配置上限，中文三/四字节与字形资源会更快消耗预算。
【待实机验证】每页延迟、峰值 heap/PSRAM、字库缓存、长段落和大型书籍性能。
本轮没有运行官方模拟器、Catch2、完整渲染或固件构建。

## 中文适配顺序

【推断】先形成原创离线中文排版原型和回归集：
严格 UTF-8 → 汉字/中英混排 token → 中文禁则与标点成组 → 字体许可/覆盖/缓存预算 →
分页/字号/跳转/进度一致性 → 官方书架与导入。
自研极简中文阅读上层，以用户此前自制固件的交互、分页、排版与功能设计为重要参考。
官方阅读代码是研究与可选复用对象，不预定完整继承其引擎或 UI；经许可和兼容性审计再选择组件。
通过平台适配层利用可合法复用的官方显示、存储、电源、USB 和原厂阅读遥控支持。
当前以真实FIX6内部参考为算法基线，已完成审计/纯算法测试；保留本页官方研究证据，
不把主机测试或单元目标编译称为完整固件移植。详见docs/12。
