## 通知与现有映射

【源码确认】[src/Inputs/TTRemoteInput.cpp:235](https://github.com/sindarin-inc/embedded-app/blob/7dcf0850daa5cec076c8d68e2f56cf413ff707aa/src/Inputs/TTRemoteInput.cpp#L235) 只接受2字节，
按 (data[0]<<8)|data[1] 合并16位通知；忽略 TT_NONE，调用 DecodeTurntouch 后 callback_。
真实调用的是 TurnTouch.cpp，不能把 RemoteInput.cpp 的 DecodePageTurner 当作这条调用链。

| TurnTouch 通知 | 原厂逻辑事件 |
| --- | --- |
| N_PRESS=FE00、N_HOLD=FEFF | UP=5 |
| S_PRESS=F700 | DOWN=D |
| W_PRESS=FB00 | LEFT=8 |

| E_W 组合=F900、N_DOUBLE=EF00 | ENTER=9 |

【源码确认】[src/Inputs/TurnTouch.cpp:3](https://github.com/sindarin-inc/embedded-app/blob/7dcf0850daa5cec076c8d68e2f56cf413ff707aa/src/Inputs/TurnTouch.cpp#L3) 还定义多组双击/组合，但当前多数映射为 NONE。

RemoteInput.hpp 另有 PT_C/五方向及不同组合编码；常量和 TurnTouch 的 N/S/E/W 事件不足以确定五个实体键的完整映射。
键数为用户已确认事实；实体布局与实际编码对应关系仍待核验，保留上述源码研究结果。

## 接口规划

【推断】InputEvent 提案保留逻辑 action、source、timestamp 与可选 raw_code，
只有原始证据足够时填 gesture；现有 RemoteCommand 已折叠短按/长按，不能凭逻辑事件重建。
InputEvent 仅作为阅读控制接口，继续原厂翻页、菜单路由；不得转发至九宫格输入法。
九宫格使用未来独立单手实体输入硬件，经独立适配层产生 CompositionEvent。
其按键数量、布局、连接协议和通信方式均未确定；原厂 BLE 链路不限定该设备。
禁止用原厂五键方向移动、逐格选择屏幕九宫格来代替专用输入硬件。
